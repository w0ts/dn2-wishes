# Stock pages' values in units (build option DN2_STOCK_UNITS)

The User (2026-11-11): *"can we start an agent on putting proper values (with unit when it fits) every where ? we could
gate it with a compile option at first"*, and *"we will need to find what value correspond what value with unit"*.
This page is that mapping, one row per stock 1.12 record, and how each was found.

## The option

- Built only with `DN2_STOCK_UNITS` set (not empty, not `0`) when the code is generated (`scripts/gen_waverider_code.py`,
  `dnfw.waverider.pages.stock_units_on`). Without it the generated header and the C are exactly as before: the build of
  this commit without the option has the same sha256 as the build before it (3637b7b3…, measured 2026-11-11).
- `dnfw.mnm.units.STOCK_UNITS`: record -> kind, curve, stock 1.12's formatter at that record. `md_page.c` `stu_*`:
  `stu_poll` (every UI loop) puts ours on each listed record whose formatter is still stock's own, so a record another
  part of ours holds (our machines', FDN8's, XDLY's, the A2 filters') is left to it; the machines' records (200..300)
  read ours only on a stock machine's track. Cost: USB image +606 B, C chunk +2,256 B (phase 1).
- A build with the option is not what the committed `waverider_code.json` holds: regenerate with the variable set, and
  run the gate's `code-fresh` with it set too.

## How a value is found (the "how" column)

1. **Our formula**: the knob's value is computed by code we have (none of the stock rows yet).
2. **SHARC runner**: Elektron's own DSP code run in the emulator at several knob values, a curve fitted; the points and
   the largest error are listed with the row (phase 2). The runner models the track's machine, filter and amp
   envelope (`scripts/sharc_waverider_m5.py`); the send FX and master are not in its render path, so their routines are
   called on their own as `sharc_xdly_step.py` does.
3. **On the unit**: what the runner cannot measure reliably goes on a list for the remote test channel (remoteui), only
   with the User's OK through the main session.
4. **% of the range**: a plain amount (a level, a send, a mix, a depth) whose physical meaning we have not measured:
   `(knob x 100 + 63) / 127` %, saying where the knob is, not a physical value (phase 1).

## Phase 1: 62 plain amounts in %

Proven in the 1.12 emulator, the option ON against OFF on the same snapshot: every value inside its cell, the other
cells unchanged (WaveTone SYN page 2 DRIF 78 -> 61%; FLTR SUS 19 -> 15%, RESO 8 -> 6%; AMP SUS 93 -> 73%,
VOL 127 -> 100%; FX OVER 35 -> 28%; LFO SLEW 8 -> 6%). Not seen on a screen yet: chorus, delay, reverb, input,
master, compressor pages, FM TONE / FM DRUM / SWARMER (the same code and table; the host test runs every row).

## Phase 2: measured units

Measured so far (`scripts/stock_units_measure.py`, run in the bench container; each quantity's table is below):

- **AMP ATK** (62): 0 ms .. 30.3 s, every knob measured (an exact table).
- **AMP DEC** (64): the time to fall 60 dB, 0 ms .. 29.4 s, 127 INF (no fall), every knob measured.
- **FLTR Multimode FREQ** (36): the cutoff (the 2-pole low-pass's -90 degree point), a fitted law
  `2^(2.2692 + 0.09521 knob)` Hz = 4.8 Hz x 2^(knob / 10.5): 10.5 knobs an octave.

  | knob | 32 | 40 | 48 | 56 | 64 | 72 | 80 | 88 | 96 | 104 | 112 | 120 | 124 |
  |---|---|---|---|---|---|---|---|---|---|---|---|---|---|
  | measured Hz | 41.6 | 68.4 | 115.8 | 196.2 | 332.5 | 586.0 | 960.0 | 1618 | 2745 | 4581 | 7776 | 13098 | 17076 |
  | the law | 39.8 | 67.5 | 114.5 | 194.1 | 329.2 | 558.1 | 946.2 | 1604 | 2720 | 4612 | 7819 | 13257 | 17262 |
  | error | +4.3 % | +1.3 % | +1.1 % | +1.1 % | +1.0 % | +5.0 % | +1.5 % | +0.8 % | +0.9 % | -0.7 % | -0.5 % | -1.2 % | -1.1 % |

  Knobs 32..64 with a 16,384-sample window, 72..124 with 2,048 (72's +5 % is that window's resolution: 64 read
  +2.8 % with it, +1.0 % with the long one). **Not measured**: knobs 0..31 (a cutoff under ~40 Hz: the track's own
  DC blocker, ~10 Hz, masks it) and 125..127: the law extrapolated. The page's 17-point curve adds up to ~3 % between
  its points.

Still to measure: the rows marked *(phase 2)* in the table (the other filter types, the filter envelope, AMP HOLD,
REL and DEL, LFO speed and phase, the send FX's times and filters, compressor, BR/SRR, the machines' envelopes and
tunes). AMP REL needs a note-off, which these renders do not make yet.

## Measured

### amp_attack (records 62): ms

the amp envelope's attack: 0 to full, linear in amplitude.

How: SHARC runner, stock 1.12 section 7 (scripts/stock_units_measure.py env --param atk): WaveTone track, every other amp field 0, SUS 127; the gain a block = rms(amp out) / rms(amp in); time = 1 / (rise a block) x 0.667 ms; knobs 1..12 from the samples' own rise (a ramp of a few blocks). ### amp_decay (records 64): ms

the amp envelope's decay: the time to fall 60 dB (exponential, a constant ratio a block, towards SUS); 127 does not fall (INF).

How: SHARC runner, stock 1.12 (stock_units_measure.py env --param dec --sus 0): the ratio of successive blocks' gain r, time = 0.667 ms x ln(0.001) / ln(r). Every knob measured.
