# TB303: an acid bass on the DN2 (fork, not released)

An eighth Monomachine-style machine, **TB-303 / 303** in MACHINE SEL (machine type 19). A port
of the **Open303** engine (Robin Schmidt, MIT) as **Schwung 303** configures it (Charles Vestal,
github.com/charlesvestal/schwung-303, GPL-3.0-only; THIRD-PARTY.md): its Devilfish modifications
off, without its drive stage (the DN2's track has overdrive).

`src/dnfw/mnm/tb303.py`, in the DSL: one program for the SHARC code and its run-mode model.

## The page

| knob | what | range |
|---|---|---|
| CUT | the filter's cutoff | 314..2394 Hz, exponential (Schwung's) |
| RES | resonance | 0..100 % |
| ENV | the filter envelope's depth (Open303's measured env-mod mapping) | 0..100 % |
| DEC | the filter envelope's decay (an accented note: 200 ms) | 200..2000 ms |
| ACC | 0: a plain note; above 0 the note is accented, by ACC | 0..100 % |
| SLID | 0: a note (the envelopes start again); above 0 the note slides from the last, over SLID's time | 2..360 ms |
| WAVE | saw .. square (Open303's blend) | 0..100 % |
| TUNE | semitones on the note (A4 440 Hz) | -24..+24 |

ACC and SLID are the 303's per-step accent and slide in one knob each: p-lock them on the steps
that accent or slide. MACHINE SEL starts it at CUT/RES/ENV/DEC in the middle, no accent or slide,
the saw.

## The DN2's notes against Open303's

Open303 tells a slide from a retrigger by note-off timing (a note on while one is held slides).
The DN2 gives a trig per step and no note off to the machine, so: every trig is a note on after a
note off (the filter and amp envelopes start again), unless SLID: then Open303's slideToNote
(the pitch glides, the envelopes go on, the accent's state changes). The amp envelope is never
released: the DN2's own amp envelope gates the track, and Open303's decays (1.23 s) as it does
while a note is held. Velocity has no input here; ACC is the step's accent. The volume is
-6 dB (Schwung's default -12 dB, times 2): a plain saw peaks near 0.58, full accent near 2.1,
before the DN2's amp (at 0 dB a fully accented saw reached 4.15, past the SHARC runner's bound
of 4).

## Against Open303

- **The oscillator.** Open303 reads band-limited mip-mapped wavetables (2 shapes x 12 levels x
  2048 doubles, 394 KB, built by FFT): far too big to ship. Here the two shapes are computed: the
  saw's two ramps with a poly-BLEP at its step (which sits between table points 1023 and 1024),
  the square as Open303 makes it, -tanh(69.98 saw + 4.37) half a cycle on, with a poly-BLEP at
  its jump; from 43 Hz on (mip level 1 and up) their DC is taken off, as the FFT takes it off.
  Against Open303's own tables (the rest of the engine the same, float64): 63..86 dB, notes
  30..84, saw, square and blends.
- **The elliptic decimation filter** as six second-order sections (the same transfer function):
  Open303's direct form II does not survive float32 (rounded, its poles leave the unit circle and
  the output blows up). The sections in float32: 90 dB from the float64 original.
- **The phase** is a 32-bit integer (a float32 phase drifted 0.2 % of a cycle over a step).
- **exp2** for the pitch and the cutoff: the float exponent's bits and a degree-6 polynomial
  (2.6e-9); PERC's exp2 table (2.3e-4) put the resonant filter's ringing out of phase within a
  step. tanh (the square) uses PERC's table; e^y with y small (the envelopes' coefficients) a
  cubic series.

## Numbers

44.1 kHz in PERC's stream (Open303's rate), 4x oversampled inside (176.4 kHz) as Open303.

Cost, the whole voice in a DN2 block (the model's steps, `test_perc_live`'s method): **saw 52,140,
square 63,577** (its tanh four times a sample), so `MNM_COST` 70,000. The machine itself, a
32-sample block: 37,620 (saw) / 49,018 (square).

Size: PERC's code grew 5,162 bytes to 128,290, its L2 span 5 KB to 0x1F800
(SMP_SW 0xbefc00).

## Checks (this fork)

`open303_ref.py` (outside the repo, `dn2mk2-scratch/plaits303/ref303/`) is a Python port of Schwung
303's Open303, held to the original C++ compiled locally: 193.6 dB at worst over eight cases (and
bit for bit with the C++'s own tables loaded; the only difference is numpy's FFT against Ooura's).

The run-mode model (the program the SHARC runs, `compare_tb303.py`) against that reference, driven
as the DN2 drives the machine (a trig every 2,752 samples, ACC and SLID as above), 11,008 samples
a case:

| case | SNR |
|---|---|
| saw, middle knobs | 63.0 dB |
| saw, resonance and env mod high, two notes | 59.3 dB |
| square, a plain and an accented step | 63.1 dB |
| slides (two slides between plain notes) | 56.7 dB |
| filter open, blend 50 %, notes 60/72 | 62.6 dB |

**Not done**: the ship gate needs the owner's bench; no build of this branch is cleared to flash.
Unverified on hardware: the sound, the DSP time on the unit (the heaviest of our machines after
DDRW/VO-6, which are gone), the page.
